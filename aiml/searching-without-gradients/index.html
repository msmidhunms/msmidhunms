Searching without gradients

Some of the hardest searches in machine learning have no gradient to follow, and every try is expensive. I met this problem twice in the same project: choosing how to build a model, and finding the input that makes a trained generator produce a given motion.

01 · The problem

A landscape you can only sample

Imagine a hilly landscape in fog. You want the lowest point, but you cannot see the slope: you can only stand somewhere and read the height. Each reading costs time. Training a neural network uses gradients to roll downhill, but some questions sit outside that: the network's own design, or a search through a model that cannot be inverted. Those need a strategy for where to look next.

03 · Methods

How each strategy picks the next try

Grid search

Tries every combination on a fixed grid. Simple and thorough, but the number of tries multiplies with every setting added.

Small spaces, two or three settings

Random search

Samples at random. Covers more distinct values of each setting than a grid for the same budget, which matters when only a few settings really count.

A strong, cheap baseline

Bayesian optimisation

Fits a model of the landscape to the tries so far, then picks the point that balances "probably good" with "still unknown".

Very expensive tries, such as training runs

Evolution strategies

Keeps a population of candidates, mutates the best ones and narrows the search as it improves. Includes GA, DE, ES, CMA-ES, ISRES and SRES.

Rugged landscapes with many decoys

Pattern Search

Steps in fixed directions from the current best point, and halves the step when nothing improves. No randomness in the moves themselves.

Fast, local refinement

Early termination

Not a search order but a saving: Hyperband and BOHB stop weak training runs early and give the freed time to promising ones.

Training runs on a shared GPU cluster
04 · Where I used it

Two searches in one project

Outer loop · designing the model

Hyperparameter search on a GPU cluster

  • Searched the depth, kernel sizes, bidirectional LSTM, dropout, activation and normalisation of the generative models.
  • Ran trials in parallel on the lab's GPU cluster in containers, with early termination to save compute.
  • Used the search history to see which settings mattered most.
Inner loop · using the model

Latent-space search in a trained generator

  • A GAN has no encoder, so it cannot say which z produces a given trajectory. This search recovers it.
  • Compared a nearest-neighbour lookup with seven optimisers: GA, DE, ES, CMA-ES, ISRES, SRES and Pattern Search.
  • The trade-off is accuracy against computation time. See Learning a task as a game for the generator.
